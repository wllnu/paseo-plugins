Notify users when uploads finish

Users get a bell notification, and an email if they opted in, when an upload finishes processing, so they stop refreshing the page.

  • Size M
  • Area uploads, top bar
  • New 1 table, 1 worker
  • Risk medium

Open: should notifications expire? Proposed: delete after 90 days.

Task

  • Bell in the top bar with an unread count
  • One notification per finished or failed upload
  • Opt-in email per upload, one toggle in the profile
Delivery
Queue consumer on upload events, not inline in the upload worker
Email
Off by default assumed
Out of scope
Push, mobile apps, preferences beyond one toggle
Context
  • Events: upload.processed, upload.failed from src/workers/upload.ts
  • Queue consumer pattern: src/workers/thumbnails.ts
  • Realtime: existing user:{id} websocket channel
  • Mail: src/mail/ mjml templates, mail catcher on :1080 in dev

Guardrails

Always

  • Idempotent on upload_id
  • Migrations reversible

Ask first

  • New dependencies
  • Changes to the upload worker

Never

  • Edit or skip existing tests
  • Fail an upload because a mail failed

Done when

  • Bell count updates within 5 s of processing

    Upload in dev, navigate away, watch the bell. E2E: pnpm e2e notifications.

  • Opted-in users get exactly one email per upload

    Toggle on, upload twice: mail catcher shows 2 mails. Replayed event sends none.

  • A failed upload notifies with a retry link
  • pnpm test and pnpm typecheck pass
