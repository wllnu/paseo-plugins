Notify users when uploads finish

Users get a bell notification, and an email if they opted in, when an upload finishes processing. It reuses the existing job queue.

  • Size M
  • Files 7
  • Risk medium
  • New 1 table, 1 worker

Open: should notifications expire? Proposed: delete after 90 days.

Done when

  • Bell count updates within 5 s of processing
  • Opted-in users get exactly one email per upload
  • A failed upload notifies with a retry link
How to verify
  1. Upload, navigate away, watch the bell: ≤ 5 s.
  2. Enable the email toggle, upload, check the mail catcher: exactly 1 mail.
  3. pnpm test notifications passes.

Scope

In

  • Bell dropdown with unread count
  • Opt-in email per upload

Out

  • Push and mobile apps
  • Preferences beyond one toggle

Approach

  1. Upload worker emits upload.processed
  2. Notify consumer new
  3. notifications one row per event
  4. Bell + email websocket, mailer
OptionTrade-off
Queue consumerDecoupled, free retries; one more worker
Inline in upload workerFewer parts; a mail failure fails the upload

Steps

  1. Schema notifications table
    • Columns: id, user_id, kind, payload jsonb, read_at, created_at
    • Index (user_id, read_at)
  2. Service create and mark read

    createNotification(userId, kind, payload), markRead(id) in src/notifications/service.ts.

  3. Consumer events to notifications
    • Subscribe to upload.processed and upload.failed
    • Enqueue a mail job only when user.emailOnUpload
    • Idempotent on upload_id; queue retries are on
  4. API list and mark read

    GET /api/notifications, POST /api/notifications/:id/read; auth via the session middleware.

  5. Bell dropdown in the top bar

    Subscribe to the existing user:{id} websocket channel; unread count from the list response.

  6. Email template and opt-in toggle
  7. Tests service, consumer, bell e2e

Risks

  • Each open tab shows the toast → acceptable for v1
  • Bulk uploads flood the mailer → batch per user per minute

Decisions

Channels
Bell and email; no push
Email
Opt-in, off by default assumed
Failures
Notify, with a retry link
